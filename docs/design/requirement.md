## 1. 项目概述 (Project Overview)

### 1.1 项目背景
羽毛球比赛视频通常包含大量非对抗性内容（如捡球、发球准备、休息、换边等），导致视频冗长。用户希望自动剔除无效片段，仅保留精彩的对抗回合（Rally）。

### 1.2 核心目标
开发一套自动化视频处理工具，通过识别视频中的**运动强度**与**音频特征**，自动分割并提取羽毛球对抗片段，生成高光集锦。

### 1.3 核心价值
- **效率提升**：无需人工手动剪辑，自动化处理。
- **体验优化**：去除垃圾时间，提升观看流畅度。
- **技术验证**：验证基于计算机视觉（CV）与音频分析的多模态融合方案在体育视频领域的可行性。

## 2. 业务逻辑定义 (Business Logic)

系统需根据以下特征区分“保留片段”与“删除片段”。

### 2.1 保留场景 (Target Scenes)
**特征定义：高运动量 + 高频节奏**
- [ ] 双方在球场范围内。
- [ ] 存在连续的来回挥拍动作。
- [ ] 羽毛球处于高速飞行状态。
- [ ] 运动员移动幅度明显且频繁。

### 2.2 删除场景 (Excluded Scenes)
**特征定义：低运动量 + 低频/静止**
- [ ] 捡球过程。
- [ ] 发球前的准备与等待。
- [ ] 局间换边、聊天、休息。
- [ ] 比赛停顿（如裁判介入）。
- [ ] 画面中无人运动。

### 2.3 核心判定公式
$$ \text{Score} = \alpha \times \text{MotionIntensity} + \beta \times \text{AudioEnergy} $$
- 当 `Score > Threshold` 时，判定为对抗阶段，予以保留。
- 当 `Score < Threshold` 时，判定为无效阶段，予以剔除。

## 3. 功能需求 (Functional Requirements)

### 3.1 视频输入与预处理
- **FR-01**：系统应支持常见视频格式输入（如 MP4, MOV, AVI）。
- **FR-02**：系统应能提取视频的帧序列与音频轨道。
- **FR-03**：支持配置视频分辨率缩放，以优化计算速度（建议预处理至 720p 或更低进行计算）。

### 3.2 运动量检测模块 (Motion Detection)
- **FR-04**：系统需逐帧计算相邻帧的差异值（Frame Difference）。
- **FR-05**：系统需生成时间 - 运动强度序列（Time-Motion Series）。
- **FR-06**：支持设置运动量阈值（默认值需可配置，例如 `motion > 10`）。
- **FR-07**：**节奏过滤**：单一帧的高运动量不足以触发保留，需满足“连续运动时长”要求（例如：连续 `>= 3 秒` 超过阈值）。

### 3.3 音频信号检测模块 (Audio Analysis)
- **FR-08**：系统需提取音频能量包络（Volume Envelope）。
- **FR-09**：系统需检测音频瞬态（Onset Detection），识别击球声（“啪”声）。
- **FR-10**：单位时间内击球声密度高时，提高该片段的保留权重。

### 3.4 片段分割与导出
- **FR-11**：根据判定结果，生成时间戳片段列表（Start Time - End Time）。
- **FR-12**：调用 FFmpeg 对原视频进行无损裁剪。
- **FR-13**：支持将多个片段无缝拼接为一个完整视频。
- **FR-14**：支持保留或移除原音频轨道。

## 4. 技术方案与实施阶段 (Technical Implementation)

为降低风险并快速验证，项目分两阶段实施。

### 4.1 第一阶段：MVP (基于视频运动量)
**优先级：P0 (必须实现)**
- **算法**：OpenCV 帧差法 (`cv2.absdiff`)。
- **逻辑**：
  1. 读取视频流。
  2. 计算当前帧与上一帧的像素差异均值。
  3. 生成运动强度曲线。
  4. 应用阈值过滤与时间窗口平滑（去除噪点）。
  5. 输出有效时间段。
- **依赖**：Python, OpenCV, FFmpeg。
- **优势**：实现简单，计算成本低，对羽毛球“动 - 静”分明特点有效。

### 4.2 第二阶段：优化版 (多信号融合)
**优先级：P1 (强烈建议)**
- **算法**：运动量 + 音频节奏融合。
- **逻辑**：
  1. 引入 `librosa` 库分析音频。
  2. 识别击球瞬态（Onset）。
  3. 加权计算最终得分：`Final_Score = 0.6 * Motion + 0.4 * Audio_Onset_Rate`。
- **解决痛点**：
  - 误判捡球时的跑动（有运动无击球声）。
  - 误判摄像机晃动（有运动无击球声）。
  - 漏判静止镜头下的快速挥拍（运动量小但有击球声）。

## 5. 非功能需求 (Non-Functional Requirements)

- **NFR-01 性能**：处理速度应优于实时播放速度（例如：10 分钟视频处理时间 < 5 分钟）。
- **NFR-02 准确性**：
  - 对抗片段召回率（Recall） > 90%（尽量不漏掉好球）。
  - 无效片段剔除率 > 80%（尽量多删垃圾时间）。
- **NFR-03 兼容性**：支持 Windows/Linux/Mac 主流操作系统。
- **NFR-04 可配置性**：阈值、最小片段时长、融合权重等参数需通过配置文件（如 `config.yaml`）管理，严禁硬编码。

## 6. 验收标准 (Acceptance Criteria)

| 测试项 | 输入 | 预期结果 | 通过标准 |
| :--- | :--- | :--- | :--- |
| **基础运动检测** | 包含明显挥拍与静止的视频 | 生成正确的时间片段列表 | 挥拍段被标记，静止段未被标记 |
| **抗干扰测试** | 包含裁判走动、观众走动的视频 | 不误判为对抗片段 | 结合音频或时长过滤后，误判率 < 10% |
| **边界测试** | 极短的对攻（<2 秒） | 可配置是否保留 | 符合配置文件中 `min_duration` 设定 |
| **输出完整性** | 完整比赛视频 | 输出剪辑后的 MP4 文件 | 文件可播放，音画同步，无黑屏闪烁 |

## 7. 风险与边缘情况 (Risks & Edge Cases)

1.  **摄像机抖动**：
    - *风险*：手持拍摄导致全图运动量大，误判为比赛。
    - *对策*：引入稳态背景建模（Background Subtraction）或优先依赖音频击球声。
2.  **环境噪音**：
    - *风险*：观众欢呼声过大，干扰击球声检测。
    - *对策*：音频检测侧重于高频瞬态（击球声特征），而非整体音量。
3.  **多机位/变焦**：
    - *风险*：镜头缩放导致像素剧烈变化。
    - *对策*：在需求 v1.0 中暂不支持复杂运镜，建议固定机位视频。

```python
motion_score = mean(absdiff(frame_t, frame_t-1))

    mark_as_active()

    mark_as_idle()

```
